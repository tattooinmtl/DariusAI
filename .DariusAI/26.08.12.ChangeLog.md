### Splitter live-drag fix — fixed inverted column resize

**Symptom.** Dragging the splitter between two docked panels sideways
had no visible effect on the columns; the leftmost panel inside the
left column stretched downward instead.

**Root cause** (`src/dariusai/viz/static/index.html:649` originally).
`attachSplitter` was writing
`leftPanel.el.style.flex = "0 0 " + w + "px"` on the first *panel*
inside the column wrap. But `.dock-column` is `flex-direction: column`,
so `flex-basis: ${w}px` applied to the panel's **height**, not to the
column's width. The column itself stays at its old width, the next
column doesn't move.

**Fix.** Walk one DOM hop up to find the column wrap and write the
flex onto the wrap (`wrap.style.flex = "0 0 " + w + "px"`). The wrap
lives in `#dockRow` (row-flex), so flex-basis becomes the column's
width and the next column actually shifts.

**Files.** `src/dariusai/viz/static/index.html` (one function, lines
648–680); `dariusai-harnessUpdated.md` (new entry under
`### 2026-08-12 (cont.) — splitter resize was on the wrong axis`).

### Three UI bugs from `buglist1.png`

User screenshot flagged three rendering problems in the floating window.
Fixes were applied on three independent axes:

1. **Panel-resize handle dangling outside docked panels.** The
   18×18 `.panel-resize` was positioned `absolute; right: 0;
   bottom: 0` inside every panel. For docked panels it dangled in
   empty space below the chat content and only became visible on
   hover — reading as "a button hanging off the bottom of the app".
   It duplicated the titlebar `panel-toggle` button. Hidden by
   default; only shown for `.panel.floating` where it's the real
   nwse-resize corner.
2. **Titlebar Min/Max/Close rendered as missing-glyph boxes.** The
   buttons used `─` / `▢` / `✕` Unicode glyphs; WebView2's fallback
   font doesn't carry them. `toggleMaximize` JS also set the restore
   state to a corrupted character. Replaced each glyph with an
   inline `<svg>`; restore state swaps via a `.maximized` class
   instead of mutating `textContent`.
3. **File-tree rows led with boxes.** `renderFileTree` prefixed rows
   with `"📁 "` / `"📄 "` emoji; WebView2 has no color-emoji font,
   so every row led with a rectangle. Rebuilt the row as a flex
   container with a `.ft-icon` SVG span (folder glyph in accent blue,
   page glyph for files, back-arrow for the parent row) followed by
   a `.ft-name` text span.

**Files.** `src/dariusai/viz/static/index.html` (CSS + HTML +
customize.js toggleMaximize).

**Validation.** Same suite results. JS parses clean.

## SESSION — 2026-08-12 — Session-8

Four bugs from `contextbug.png`. PATCH bump `0.63.1a0 → 0.63.2a0`.

### 1. Cumulative counter bled past the window

The chat panel's "ctx: 409,042 / 128,000 tok (–219.6% left)" was
fundamentally wrong. `cumulative_total` was a sum of every token
processed across the entire session — the user can chat for hours
without that number ever shrinking, and on long conversations it
runs well past the model's window even though any single call is
well within it. The gauge showing a *negative* percentage of the
window left was the failure mode.

**Fix.** Replaced the cumulative fields with **per-call** fields:
`current_input_tokens` / `current_output_tokens` (the size of THIS
prompt) and `total_input_tokens` / `total_output_tokens` (the
session-level sum, still tracked but not what the page renders by
default). The chat panel now uses `current_total` for the numerator
of the "% left" gauge — the actual size of the prompt being sent
to the model right now, which always fits in the window (the API
rejects oversized requests).

### 2. Negative percentage

Even with the current-input fix, a model that reports a smaller
window than the prompt actually used would still produce a negative
"% left". The chat panel now clamps:

- If `used ≤ window`: render `97.7% left` (green/amber/red by
  threshold).
- If `used > window`: render `12.3% over` (always red). Never
  show a negative number — the user can read "over" and know
  the model is reporting a mismatch.

### 3. TodoList not selectable

The phases panel lived under the chat view's `user-select: none`
default (so drag-selecting text wouldn't fight the pywebview drag
region). Phase titles couldn't be copied. Added
`user-select: text` to `.chat-todo` and `.chat-todo-title` (cursor:
text on the title, default cursor on the icon). The status icon
keeps its default cursor so the icon-click affordance is unchanged.

### 4. Agent stopped "without a final message"

The thinking box stayed open across many iterations even though the
loop had finished. Two bugs converged:

- **Iteration cap without `is_final`.** The "Paused after N tool
  calls…" note was emitted with `is_final: False` (the default).
  The chat panel uses that flag to close the thinking box and render
  the message; with `is_final: False` the box stayed open until the
  WebSocket closed or the user sent the next message.
- **Empty content blocks.** When the model returned neither text
  nor tool_use blocks, the loop broke out without emitting anything.
  The thinking box stayed open forever.

Both fixed: the loop now **always** emits a final
`assistant_text` with `is_final: True` on every exit path — the
final answer, the iteration-cap note, or a '(no response)'
placeholder for empty content. The chat panel will close visibly
no matter what the model returns.

### Backend

- `src/dariusai/agent/chat.py` — `ChatSession` gained three config
  fields (`auto_compact_enabled=True`, `compact_threshold_ratio=0.75`,
  `keep_recent_turns=6`, `tool_output_truncate_chars=500`) and two
  methods: `compact(force=False)` (the public entry point) and
  `_compact_history()` (the pipeline). The auto-hook at the top of
  the tool-calling loop fires `self.compact(force=False)` on every
  iteration; the call is a no-op unless
  `current_input_tokens >= context_window * compact_threshold_ratio`.
  When compaction runs, it emits a `context_compacted` event with the
  old/new/saved token counts.
- `src/dariusai/viz/server.py` — the `/ws/chat` loop now intercepts
  `{"type":"compact"}` payloads before treating the bytes as a user
  prompt (running JSON through `session.send()` would dump it into
  the model's context). The handler calls
  `session.compact(force=True)` and replies with
  `{type: "context_compacted", status, old_tokens, new_tokens, saved_tokens}`.

### Compaction pipeline

1. **Tool-output truncation.** Older turns (everything before the
   last `keep_recent_turns` messages) have their `tool_result`
   strings > 500 chars replaced with
   `"[Output truncated for context compaction: N chars omitted]"`.
   Recent turns are untouched.
2. **LLM summarization.** The older turns are sent to `self.llm`
   with a prompt asking for a concise summary preserving the active
   task, files created/edited, important decisions, and current state.
3. **History reconstruction.** `self.messages` becomes
   `[{user, "[Prior Context Summary]:…"}, {assistant, "Understood…"},
   ...recent]`. The pair preserves the alternating-role invariant
   that both the Anthropic and OpenAI APIs require.
4. **Summarizer fallback.** If the LLM call raises (network, rate
   limit, bad key), the chat session falls back to a deterministic
   stub `"context compacted: N earlier user turn(s); summarizer
   unavailable, full details dropped"`. The chat session never
   crashes because the summarizer tripped.
