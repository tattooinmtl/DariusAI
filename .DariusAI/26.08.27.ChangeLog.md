# Session ChangeLog — 27 August 2026

## SESSION — 26.08.27 — Session-1 — View Menu, Windows Dialog, Console & Terminal Sections (`0.78.0a0` → `0.79.0a0`)

### Summary of Completed Work

1. **New `View` menu in the menubar**:
   - `View → Windows…` — new section-placement dialog (below).
   - `View → Layout Options…` — moved out of `Settings`.
   - `View → Reset Layout…` — promoted from a button buried inside the Layout Options modal to a first-class menu entry (still confirms before wiping the arrangement).
   - `Settings` is now just `Preferences…`.

2. **Neural toggles moved to `Settings → Preferences`**:
   - "Show node labels in the 3D scene" and "Show node animations" now render in the settings body under a **Neural View** heading, alongside the other behaviour settings. They still route through `window.__neural`, so the toggles behave identically.
   - `Layout Options` is now strictly about layout: a visible/hidden checkbox and a Dock/Float button per section, plus Reset Layout.

3. **`View → Windows…` — drag sections onto a layout mockup**:
   - Modeless dialog (like Preferences) with **Sections** on the left and a thumbnail of the workspace on the right — the same nine slots (3 columns × 3 rows) the real dock overlay uses.
   - Press a section in the list and drag it onto a slot; the target cell lights up with the accent rectangle, exactly as the workspace does when docking a floating panel. Dropping places the section for real, immediately.
   - Tiles on the mockup can be dragged between slots, into the **Floating** bay to pop a section out, or back onto the list to take it out of the layout. Each tile also has a `✕`.
   - The map is live: dragging a panel in the app itself while the dialog is open redraws it (`WM.onChange`).

4. **Console — a new, real section**:
   - Connects to `/ws/events`, the same activity bus the neural view animates from: tool calls, brain searches, skills used, node edits, files saved.
   - Timestamped, colour-coded lines with a live-connection dot, text filter, Pause (queues while paused) and Clear, plus an event count.
   - Also captures `window.onerror` / `unhandledrejection`, which in a packaged desktop window would otherwise be invisible.

5. **Terminal — a new, real section**:
   - New backend [`src/dariusai/viz/terminal.py`](file:///C:/.dariusai-harness/src/dariusai/viz/terminal.py) (`TerminalSession`) and websocket `@app.websocket("/ws/terminal")`.
   - Runs real commands through the platform shell in the project directory, streaming merged stdout/stderr as it is produced. `cd` is handled in-process so the working directory sticks across commands.
   - Ctrl-C / Stop kills the whole process tree (Windows job object, reused from `agent/sandbox.py`; `killpg` on POSIX). While a command runs, typed lines are sent to its **stdin**. `↑`/`↓` walks history; `clear`/`cls` wipes the pane.
   - Line-oriented rather than a PTY — a PTY would need a compiled Windows dependency (pywinpty) to buy full-screen programs the panel isn't for.
   - Spawns via `quiet_creationflags(CREATE_NEW_PROCESS_GROUP)`, so no console window flashes onto the desktop.

6. **Both new sections start outside the layout** (`DEFAULT_HIDDEN`), so nobody's existing workspace is rearranged by the upgrade. They are built and connected at boot — they just aren't placed until dragged in from `View → Windows…`.

7. **Version bump** (`tools/bump_version.py --minor`): `0.78.0a0` → `0.79.0a0`, lock regenerated over 37 source files (`b4e945dc3ab3c24b…`).

### Follow-ups the same day

- **"The terminal is not connected to a backend"** (`0.79.0a0` → `0.79.1a0`): the running app was a `pythonw.exe` started before the change — `/api/version` on `127.0.0.1:8765` reported `0.78.0a0`, `/ws/events` opened, `/ws/terminal` was rejected **HTTP 403** (no such route in that process). The page is read off disk each load, so the new UI was talking to an old server. Current code verified good under a real uvicorn server. **Fix: restart the app** — and the panel now says exactly that when the socket has never reached `ready`, instead of "retrying…" forever.

- **Terminal built-ins** (`0.79.1a0` → `0.79.2a0`): `--info` / `-i` prints an aligned spec block — Version, Python, Platform, Shell, Directory, plus Brain (path + node/edge counts), Project, active Provider + model, and process Uptime; `--version` / `-v` prints `DariusAI <version> (<display>)`; `--help` / `-h` lists the built-ins. Implemented in `TerminalSession._try_builtin` so the version always comes from the running package. The app-specific rows arrive via an `info` callable passed in by the `/ws/terminal` route (`app.state.started_at` added for Uptime); a raising provider degrades to a `Warning` row. `darius --info` works as a prefix; `dariusai …` is deliberately left to the real console script.
