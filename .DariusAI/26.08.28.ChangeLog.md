# Session ChangeLog — 28 August 2026

## SESSION — 26.08.28 — Session-1 — Blender MCP Bridge & `/3dgame` Kit (`0.79.2a0` → `0.80.0a0`)

### Summary of Completed Work

1. **DariusAI's first MCP client** — [`src/dariusai/mcp/`](file:///C:/.dariusai-harness/src/dariusai/mcp/):
   - `client.py` — JSON-RPC 2.0 over Streamable HTTP, standard library only (no new dependency). Full handshake: `initialize` → `notifications/initialized` → `tools/list` → `tools/call`.
   - `blender.py` — `BlenderBridge`: holds no persistent socket, probes cheaply, and re-runs the handshake automatically the first time a probe comes back healthy. One process-wide bridge shared by the light, the agent tools and `/3dgame`.
   - `registry.py` — discovered MCP tools become ordinary Darius agent tools (`blender_*`; `game3d_*` keeps its own name).

2. **The Blender add-on** — [`addon/blender/darius_blender_mcp/`](file:///C:/.dariusai-harness/addon/blender/darius_blender_mcp/), re-implemented from the reference architecture in `C:\blender_addon_mcp` (**that folder was never modified**):
   - `server/protocol.py` is deliberately `bpy`-free — registry and dispatcher are pure functions over dicts, so the whole protocol is testable without Blender.
   - `server/mcp_server.py` — HTTP transport, main-thread marshalling, and `serve_background()` for headless batches.
   - `tools/` — generic Blender surface (scene, objects, materials, modifiers, render, info) plus AST-gated `execute_python`.

3. **`game3d` — the dominator replacement**, written fresh and neutral:
   - Structures: `house`, `tower`, `wall`, `gate`, `storage`, `shrine`, `workshop`; roofs `hip`/`pyramid`/`cone`/`flat`.
   - Units: `worker`, `melee`, `ranged`, `mounted`, `caster`; weapons `none`/`tool`/`sword`/`bow`/`lance`/`staff`.
   - Palettes: `stone`, `timber`, `desert`, `verdant`, `obsidian`, `frost`, `crimson`, `azure` — six roles each, so one call recolours a whole set.
   - Geometry uses `bmesh`, not `bpy.ops`, so it works in background mode where operators have no context.
   - **No DomiNations content and no faction names** — pinned by a test.

4. **Ports** — Blender MCP keeps **8765**; DariusAI's own UI moved to **8780** (`launch.pyw:88`, `cli.py` ×2, `viz/window.py:176`). They cannot share a port and 8765 was verifiably occupied by DariusAI.

5. **Endpoints** — `GET /api/blender/status`, `GET /api/blender/info`, `POST /api/blender/connect`, `POST /api/blender/install`, `POST /api/blender/launch`, `PUT /api/blender/endpoint`.

6. **UI** — title-bar connection light + isometric-cube mark: **red** not connected, **orange** reachable but wrong or unwell, **green** handshake done. Clicking opens a Blender panel with Install / Launch / Reconnect and the live tool list.

7. **`/3dgame`** (aliases `blender`, `3d`) — connects, runs `game3d_health_check`, loads the new [`addon/skills/gamedev/3dgame/SKILL.md`](file:///C:/.dariusai-harness/addon/skills/gamedev/3dgame/SKILL.md), and reports the same three states as the light.

8. **Seamless install** — `blender_integration.py` finds Blender, copies the add-on in and enables it via one headless run. Module name `darius_blender_mcp`, deliberately distinct so it cannot clobber an add-on the user already has.

### Two real bugs found by testing, both fixed

- **Double-marshalling deadlock** — tool handlers hop onto Blender's main thread, and the dispatcher was hopping them *again*; the second hop waited on the thread already blocked in the first. Caught by the real-Blender run; it would have hung every tool call in the GUI as well. `run_on_main` now runs inline when already on the main thread, and the dispatcher calls handlers directly.
- **Stale render-engine name** — Blender 5.2's enum is `BLENDER_EEVEE` (`BLENDER_EEVEE_NEXT` existed only in 4.2), and the fallback path used the invalid name itself. Engines are now resolved against what the running build reports.
